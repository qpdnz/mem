# 地図の定義 (map.json) の書き方

1つの JSON が4つの図すべての元になる。ここに無い key は書かない (検査で落ちるか、黙って無視される)。

最小構成は `meta` + `entities`。`flow` と `screens` は無ければその図のタブが消える。

## meta

| key | 要否 | 中身 |
|---|---|---|
| `title` | 必須 | 地図の題。窓の題名にもなる |
| `client` | 任意 | 誰のための地図か |
| `product` | 任意 | 対象の呼び名 |
| `description` | 任意 | 3〜4行。**何を見せる地図で、何を見せていないか** |
| `generatedAt` | 任意 | 作った日 |
| `basis` | 任意 | **どの commit・いつまでの実測から作ったか。**地図が写しである印 |
| `back` | 任意 | `{ "label": "← 戻る", "href": "../" }` 左上に出る戻り口 |
| `words` | 任意 | 言葉の点検表。図には出ない。`check_words.py` が読む |

実体・関連・項目の件数は定義から数えて出るので書かない。

### meta.words (言葉の点検表)

```json
"words": {
  "same": [["persona", "担当"], ["台帳", "黒板"]],
  "avoid": { "席": ".rule/vocabulary.md 使わない語 (persona の2つ目の名前)" }
}
```

- `same` — **同じ物を指す呼び方の組。**組の中の2つ以上が表示名に出ていたら表記ゆれとして挙がる。どれを正にするかは人が決める (機械には同義が分からないので、ここに書かないと見つからない)
- `avoid` — **使わないと決めた語と、その理由。**理由は出典 (裁定・規約の path) を書く

この表に無くても、**repository に1件も出てこない語**は `check_words.py` が自動で挙げる。

## layers (層)

実体と画面の色分け。上から順に並べる。

```json
{ "id": "ledger", "label": "第2層 台帳 (engineが残す記録)", "short": "台帳",
  "note": "engineが残す記録 (消さずに足す)", "color": "orange" }
```

`color` は `blue` `orange` `green` `purple` `teal` `red` `gold` `pink` `gray` か `#rrggbb`。
`short` は箱の中の小さな札と**凡例の見出し**に使う (省くと `label` を使う)。
`note` は**凡例に出る1行の説明。**「この色は何を表すのか」を日常語で書く。

図の左下に凡例が出て、押すとその色だけを残して他が薄くなる。
`flow` では層ではなく `actors` の色が出る (`actor` にも `note` を書ける)。
根拠: PO指摘 2026-09-18「ER 色ついてるけど、なにがなんだか分からんな」。
層の名前は箱の中の小さな札にしか出ておらず、色と意味を結ぶ物がどこにも無かった。

## entities (実体)

```json
{
  "id": "loans",
  "name": "貸出",
  "physical": "loans",
  "layer": "lending",
  "summary": "1冊を1人へ貸した記録。返却で閉じる。",
  "at": [3, 1],
  "erAt": [3, 2],
  "source": ["src/.../Vo_Loan.cs:1-20", "実測 2026-09-16: 12,180件"],
  "notes": ["補足の行 (右の欄に出る)"],
  "fields": [ ... ]
}
```

| key | 要否 | 中身 |
|---|---|---|
| `id` | 必須 | 定義の中だけの名前。`:` は使えない。業務・画面と重ねない |
| `name` | 必須 | **日常語。**初めて見る人が読む言葉 |
| `physical` | 任意 | 実装での名前 (table名・path)。長いと箱で省略されるので30字程度まで |
| `layer` | 任意 | `layers` の id |
| `summary` | 任意 | 1〜2文。「これは何を表す物か」。**箱に触れると出る** |
| `at` / `erAt` | 任意 | `[列, 行]` の格子位置。`scripts/layout.mjs` が探して書く。省くと簡易な自動配置。`erAt` は ER図だけ別位置にしたい時 |
| `source` | 任意 | 文字列か文字列の配列。**開いて確かめた `file:行` だけ** |
| `notes` | 任意 | 補足の行 |
| `fields` | 任意 | 項目 (下) |
| `code` | 任意 | 項目をコードから作る時の結びつけ (下) |

### code (コードへの結びつけ)

C# の宣言から項目を作る時に付ける。`scripts/refresh_from_csharp.py` が読む。

| 書き方 | 作る項目 |
|---|---|
| `{"types": ["Vo_WorkSession"]}` | 型のプロパティを宣言順に (JSON 名があればそれを物理名にする) |
| `{"types": ["Vo_X"], "file": "src/engine/"}` | 同名の型が複数ある時、置き場の一部で選ぶ |
| `{"types": ["Inf_X"], "expand": ["patterns"]}` | 一覧の要素型の項目を `patterns[].子` として足す |
| `{"enum": "EBlaBor__Field", "prefix": "task"}` | enum の値を項目にする (DB の列名を enum で持つ場合など) |
| `{"table": "history"}` | DDL の `CREATE TABLE` の列 |

項目側の印:

| key | 意味 |
|---|---|
| `manual: true` | コードと無関係な項目 (file名・本文など)。位置ごと残す |
| `auto: true` | コードから足されてまだ名前が無い。画面に「未命名」と出る |
| `unused: true` | 宣言だけで読み書きする所が無い。画面に「未使用」と出る |

### fields (項目)

```json
{ "name": "利用者ID", "physical": "member_id", "type": "uuid", "key": "FK", "ref": "members", "nullable": true,
  "values": ["waiting", "running"], "note": "空だと自由記述の行" }
```

| key | 中身 |
|---|---|
| `name` | 日常語の項目名 (必須) |
| `physical` | 実装での名前。ER図の2列目、検索の対象 |
| `type` | 型。`uuid` `int` `enum` `TEXT` など、対象の言葉のままでよい |
| `key` | `PK` / `FK` / `UQ`。複数なら `"PK,FK"` か `["PK","FK"]` |
| `ref` | 参照先。`entity_id` か `entity_id.物理名`。**存在しないと検査で落ちる** |
| `nullable` | `true` で「空可」と出る |
| `values` | 取り得る値。enum は**メンバー名 (と数値)** を並べる |
| `note` | その項目の意味・制約・実測 |

## relations (関連)

**親 (1側) → 子 (N側)** の向きで書く。`label` は親から見た言葉。

```json
{ "from": "members", "to": "loans", "card": "1:N", "label": "借りる", "via": "member_id", "optional": true }
```

| key | 中身 |
|---|---|
| `from` / `to` | 実体の id (必須) |
| `card` | `1:1` `1:N` `N:1` `N:N` |
| `label` | 線の上に出る言葉。**「持つ」より具体的な動詞** |
| `via` | **子側**の FK 項目の物理名。ER図で行から行へ線を引くために使う |
| `optional` | `true` で点線。任意の参照・仕組み上のつながりに使う |

自分自身への関連 (`from` と `to` が同じ) は線にならない。項目の `ref` で示す。

## flow (業務の流れ)

```json
"flow": {
  "actors": [{ "id": "staff", "label": "司書", "color": "orange" }],
  "steps": [
    { "id": "lend", "actor": "staff", "title": "貸出手続きをする", "at": [2, 1],
      "summary": "カードと本を読み取って貸し出す。", "does": ["カードを読む", "期限を伝える"],
      "uses": ["loans", "copies"], "screen": "sc_counter", "source": "..." }
  ],
  "links": [{ "from": "lend", "to": "return", "label": "返却まで", "dashed": true, "both": false }]
}
```

- `title` は15字程度まで。**動詞で終える** (「配車する」「棚へ落とす」)
- `summary` と `does` は**箱に触れている間だけ箱の外へ開く。**押して右の欄を読まなくても分かる。開く札は箱の大きさに入らないので、並びは動かない
- `uses` は実体の id。箱の下に名前が並び、右の欄からその実体へ飛べる
- `screen` は画面の id。人がその画面でやる段階にだけ付ける
- `links` は矢印。`both: true` で両向き、`dashed: true` で点線 (条件付き・確認できていない経路)

## screens (画面)

```json
{ "id": "sc_counter", "no": "03", "title": "貸出カウンター", "route": "counter", "layer": "lending",
  "at": [1, 1], "summary": "カードと本を読み取って貸し出す。",
  "does": ["カードを読む", "本を読む"], "uses": ["loans", "members"], "source": "...",
  "mock": [ ... ] }
```

`screenLinks` は `{ "from": "...", "to": "...", "label": "..." }` の配列。

### mock (画面の線画)

箱の中に描く小さな枠。**本物そっくりにしない。**その画面で目立つ物を3〜5個並べれば足りる。

| 書き方 | 出る物 |
|---|---|
| `{ "h": "見出し", "tag": "右の小札" }` | 見出し行 |
| `{ "text": "説明" }` | 灰色の一行 |
| `{ "input": "検索…" }` | 入力欄 |
| `{ "fields": [["季節","秋"],["品数","24"]] }` | ラベル付きの値の並び |
| `{ "list": [["行の左","右"], …] }` | 一覧 |
| `{ "table": { "cols": ["書名","期限"], "rows": [["…","9/30"]] } }` | 表 |
| `{ "chips": ["全部","小説"], "active": 0 }` | 絞り込みの札 |
| `{ "tabs": ["A案","B案"], "active": 0 }` | タブ |
| `{ "cards": [{ "title": "A案", "lines": ["原価 27.4%"] }] }` | 横並びの小カード |
| `{ "buttons": [{ "label": "確定", "primary": true }, "やめる"] }` | ボタン |
| `{ "kpi": [["本日の返却", "42"]] }` | 大きい数字 |
| `{ "log": ["10:02 返却", "10:05 取置"] }` | 等幅の記録 |
| `{ "graph": 7 }` | 節と線の絵 (数はだいたいの節の数) |
| `{ "split": [[…左…], […右…]], "ratio": [3, 2] }` | 左右分割 |

## terms (用語集)

5つ目のタブ。**この地図を初めて見る人が、図の言葉を引くための頁。**省くとタブごと消える。

```json
"terms": [
  { "id": "w_report", "word": "報告", "short": "4つの違う物がこう呼ばれる。どれかを名指しする",
    "means": "(1) 完了報告 = AI が仕事を終えた時に書く file。(2) ticket = …",
    "confuse": "人が書くのは (4)、AI が書くのは (1)(3)。「報告が来た」だけでは、どれか分からない。",
    "see": ["completion_report", "ticket"] }
]
```

| key | 要否 | 中身 |
|---|---|---|
| `id` | 必須 | `w_` で始めると実体のidと混ざらない |
| `word` | 必須 | 図に出ている語そのまま。**1語1項目** (同じ語を2つ書くと検査で落ちる) |
| `short` | 必須 | 1行。札に出る |
| `means` | 任意 | 2〜4文。日常語で書く |
| `confuse` | 任意 | **取り違えやすい点。**書くと札に「まぎらわしい」の印が付き、欄では意味より先に出る |
| `see` | 任意 | その語が指す実体・業務・画面のid。札の下に名前が出て、欄から飛べる |
| `source` | 任意 | 出典 |

- `means` と `confuse` は**札に触れている間だけ札の中に開く** (押して選んでも同じ)。右の欄を開かずに読める
- **`confuse` は本当に取り違える語だけに書く。**全部に付けると印の意味が消える (実測 2026-09-18: 36語中25語に付けたら、印が「ただの飾り」になった。16語へ減らした)
- 札の色は `see` の最初の実体の層に合わせる。図で見た色のまま並ぶ
- `see` が重なっている語どうしは、欄に「関係する語」として自動で出る
- 実体の欄からも「この図で使う言葉」として逆に辿れる

## demo (▶ の筋書き)

```json
"demo": { "title": "1件の仕事が生まれて終わるまで", "interval": 3800,
  "steps": [{ "target": "step:f_dispatch", "title": "配車する" }, { "target": "entity:loans" }] }
```

`target` は `entity:<id>` / `step:<id>` / `screen:<id>`。図は自動で切り替わる。
省くと画面 (無ければ業務) の並び順から自動で作る。

## 検査で落ちる主な書き方

| 誤り | 直し方 |
|---|---|
| `ref` / `uses` / `from` / `to` の先が無い | id の綴りを合わせる |
| `via` が**子側**の項目に無い | 親側の項目名を書いていないか確かめる。埋め込みの object には `via` を付けない |
| 同じ図で `at` が重なっている | どちらかを動かす |
| 同じ実体に同じ `physical` の項目が2つ | 物理名を分ける |
| `key` が PK/FK/UQ 以外 | 3つのどれかにする |
| id に `:` が入っている | `_` などに変える |

警告 (落ちない) は「項目が0件」「どの関連にも出てこない実体」。図で孤立してよいか一度考える。
